# Local app debugging over `app_rpc`

The app in `android/` now ships a **debug-only** RPC bridge, so it can be inspected and driven
from here: screenshot it, read its view tree, tap a container, type into a field, and call the
app's own management methods.

## What was added

| file | role |
|---|---|
| `android/app/src/debug/java/ai/pechka/factory/PechkaDebugProvider.kt` | the Binder bridge (generated by `app_rpc {"action":"template"}`, plus the methods below) |
| `android/app/src/debug/AndroidManifest.xml` | registers the provider — debug builds only, never a release APK |
| `android/app/src/main/java/ai/pechka/factory/FactoryState.java` | counter, label, last action — the one state both the UI and RPC touch |
| `android/app/src/main/java/ai/pechka/factory/MainActivity.java` | native console (status, label, input, Bump / Set label / Reset) above the WebView |

Because the screen and the RPC share `FactoryState`, a tap on **Bump** and a `factory.bump`
call are the same operation — so the RPC can be verified against what is actually on screen.

## Custom methods

| method | params | returns |
|---|---|---|
| `factory.status` | — | `counter`, `label`, `last_action`, `uptime_ms`, `package`, `version`, `ui_attached` |
| `factory.bump` | — | same, after incrementing the counter |
| `factory.reset` | — | same, counter back to 0 |
| `factory.set_label` | `{text}` | same, label replaced (empty → `factory`) |
| `factory.reload` | — | same, plus `reloaded` — reloads the bundled page in the WebView |
| `factory.toast` | `{text}` | same, plus `toasted` — shows a toast on the main thread |

Built-ins from the template also work: `rpc.methods`, `app.info`, `debug.logcat`,
`debug.crash_report`, `ui.tree`, `ui.tap`, `ui.input`, `ui.scroll`, `ui.back`, `ui.shot`.

## Install and approve (person's part)

1. Download `factory-<tag>-debug.apk` from the release the `ship` workflow just published.
2. Install it (debug-signed, so no keystore is involved).
3. Open it once so the provider is created.
4. In Settings → On-device app debugging, approve `ai.pechka.factory`, pinning the signing
   certificate the app shows.

Until step 4, `app_rpc` answers "App `ai.pechka.factory` is not approved".

## Test sequence

```
app_rpc {"action":"launch","app":"ai.pechka.factory"}
app_rpc {"action":"methods","app":"ai.pechka.factory"}
app_rpc {"app":"ai.pechka.factory","method":"rpc.methods"}
app_rpc {"app":"ai.pechka.factory","method":"factory.status"}
app_rpc {"app":"ai.pechka.factory","method":"factory.bump"}
app_rpc {"app":"ai.pechka.factory","method":"factory.set_label","params":{"text":"from rpc"}}
app_rpc {"app":"ai.pechka.factory","method":"ui.tree"}
app_rpc {"app":"ai.pechka.factory","method":"ui.shot"}
app_rpc {"app":"ai.pechka.factory","method":"ui.tap","params":{"text":"Bump"}}
app_rpc {"app":"ai.pechka.factory","method":"factory.status"}
```

Expected: `factory.bump` moves `counter` 0→1 and the screen's status line follows; `ui.tap` on
"Bump" moves it again without any RPC counter call; `ui.shot` returns a PNG into `agent/rpc/`
that shows the same numbers.

Results are logged to the SQL sandbox (`agent/sql/db/factory.sqlite`):

```
query {"db":"factory","sql":"SELECT method, ok, detail FROM rpc_calls ORDER BY id"}
```

## Notes

- The provider refuses callers other than the Pechka app (`ALLOWED_CALLER = "ai.pechka"`), and
  the app must be approved in Settings before any call is attempted.
- `ui.tap` needs a target that exists in `ui.tree`: the console's buttons carry
  `contentDescription` values (`bump`, `setlabel`, `reset`, `input`, `status`, `label`, `web`),
  which are the most stable handles.
- The APK bundles the page from the release asset, so it renders offline from `build.json`.
